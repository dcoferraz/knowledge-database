## Summary

An end-to-end audit of v0.6.0 against Claude Code produced thirteen findings;
v0.7.0 fixes all of them and adds the setup wizard. The mechanically enforced
core was already sound — every failure was at an edge no test covered: non-git
projects, planted-text freshness, subagents, the plugin payload, and the
advanced-mode documentation.

## Context / Question

Does the app work as designed — hard rules, install process, advanced mode —
specifically under Claude Code? The audit installed it fresh, in a non-git
workspace and through the plugin, ran every rule against purpose-built
fixtures, and read the docs as a new user would.

## Findings / What We Did

| # | Finding | Fix |
|---|---------|-----|
| 1 | `install.sh` exited 128 half-installed in a non-git project (the shape ADVANCED.md recommends), unrepairable on rerun | git layers skipped with a reason; report printed from an EXIT trap |
| 2 | Planted rule blocks frozen forever by the marker guard; `--check` said IN PLACE while text was 2 versions old | block generated by `kb rules --plant`, replanted when stale, KB014 warns |
| 3 | AGENT.md commanded `scripts/kb-discover` / `kb-ingest`, which no install ever copied | folded into `bin/kb` as `discover` / `ingest`, shims kept |
| 4 | Plugin ships only SKILL.md, whose bootstrap said "copy the full skeleton" with no source | `knowledge-database/bootstrap.sh` finds a source (marketplace clone, sibling checkout, shallow clone) |
| 5 | ADVANCED.md's own example entry failed KB002 + KB004 | rewritten to pass, with the reasons spelled out |
| 6 | Workspace mode voided the write-back gate entirely | nested-repo hooks + `--repo` + grace-window evidence |
| 7 | KB008 would fail the whole repo on a date nobody picked | opt-in, warns by default |
| 8 | Stop hook ignored `stop_hook_active` — a stop loop waiting to happen | `kb stop-hook` wrapper |
| 9 | No `SubagentStop`: delegated work escaped the rules | wired to the same wrapper |
| 10 | `hooks/kb-session-check.sh` orphaned, needed `jq`, emitted a non-existent Stop field | deleted |
| 11 | Stale `KB001-KB011` / `KB001-KB013` ranges across docs | corrected; planted range now generated |
| 12 | `supersede_with_consent` documented, implemented nowhere | real config switch, injected by `kb rules` |
| 13 | Installer claimed the prompt hook covered the current session | corrected: hooks are snapshotted at session start |

Two things the audit could not have found from reading alone, both caught by the
new tests: the installer rewriting `kb.config.json` tripped this repo's own
KB009 lockstep pair (see [[2026-09-04-install-state-outside-kb-config]]), and a
`STATE` variable name collided with the agent-hook state machine, silently
skipping the state write.

A fourteenth gap surfaced from the same review and landed in this version: the
app had no update path at all — see [[2026-09-04-self-update-via-kb-upgrade]] for
`kb upgrade`, the version notice, and `bootstrap.sh` becoming get-or-refresh.

Test coverage went from 51 to 94 assertions across the two suites, with a
fixture for every fix — including the non-git install, stale-block replanting,
the legacy Stop-hook migration, the loop guard, nested-repo gating, and
nested-repo `@rev` drift.
