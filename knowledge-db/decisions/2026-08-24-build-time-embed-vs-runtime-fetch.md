## Summary

INDEX.html embeds all entry content and cited source lines at build time. Rejected: runtime `fetch()` of md files (dead on `file://` — browsers block local fetch via CORS, so double-click shows an empty shell) and hosted docs (GitHub Pages/MkDocs — dependencies, hosting setup, and org-visible knowledge exposure the maintainer declined).

## Context / Question

Three ways to give non-technical users a readable KB: (A) INDEX.html with JS fetching INDEX.md + entries at open time, (B) static site generator / GitHub Pages, (C) fully self-contained HTML generated by `kb index`. The target user double-clicks a file; no server, no git, no accounts.

## Findings / What We Did

Chose (C), by maintainer directive. (A) fails the core use case: `fetch()` from `file://` is CORS-blocked, requiring a local server — kills the non-technical audience. (B) violates the zero-dependency constraint and makes knowledge exposure a hosting default rather than a choice. (C) reuses the existing "INDEX is build output" machinery (same command, same hooks, same CI), works offline, and travels as one file over email/Slack. Cost: page must be regenerated to stay fresh — handled by KB012.
